# One-URL clone workflow

For a cloning request, the user supplies the URL. Invoke this folder’s `clone.mjs` with that URL and the project as the working directory. In a workspace initialized with this version, `node clone.mjs https://example.com/` invokes the same tool. Each URL gets a new directory under clones/HOST. To select another empty directory, pass `--output DIRECTORY`. Ports default to 3010 through 3012. Use `--base-port NUMBER` for a separate set. A run records elapsed time, per-step logs, and the last stage that passed in run.json. Servers started for verification shut down at the end.

A run captures routes and browser evidence, verifies mirror replay, reconstructs the native site, verifies it, converts and assembles Svelte routes, installs dependencies, builds for production, and compares the production preview with the mirror and native site. The verifier starts production preview after building and checking the generated Svelte app. A failure stops promotion. After addressing an environmental failure, rerun the same URL with `--output DIRECTORY --resume` and the same port configuration. Certified inputs are checked before reuse. Incomplete stage directories move into attempts. Changes to workflow code require a new output directory.

Read `01-native/forensics/source-recovery.json` alongside the runnable native site. Source maps can contain original paths and text. Export identifiers, runtime observations and readable reconstructed code support different claims. Preserve their provenance. Private server files, omitted modules and stripped paths require another source of evidence to establish authorship or original placement.

The three stage skills supply implementation detail. Project-specific examples in the developer handoff blueprint describe Content Architecture. Select interaction contracts from the captured target. Preserve original fonts, gestures, composition, scrolling and responsive transitions.


## When the decoder needs newly authored source

On a partial-native exit, the agent reads the run's source-recovery.json, module-outcomes.json and route manifest. For each unresolved interaction, reproduce it on the mirror, identify its route, triggering inputs, lifecycle, frame output and cleanup, and implement it as editable source. Put that code in `repair/source/` under the run directory and the route mapping in `repair/plan.json`. Use the schema and verification criteria from the native skill’s [continuation guide](./native-stack-decompiler/references/reconstruct-runtime.md). Run the same URL with `--output DIRECTORY --resume`. The driver compiles a new candidate, retains the original partial project, runs native verification, and advances only on passing measurements. For missing evidence, record the specific route, asset or behavior still unresolved.

## Installing this revision

Keep the four skill directories, shared helpers, root manifest and lockfile together. For a clean tool installation in this folder use `pnpm install --frozen-lockfile`. The browser fixtures require Playwright Chromium. To make the launcher available in an empty workspace run `bash init-workspace.sh /path/to/workspace`. This registration links to the selected revision and checks for occupied paths first. Local skill tests are under each skill’s tests directory.

Run `pnpm run test` in the skill folder for the local fixture suites. The Svelte suite defaults to the pinned toolchain under `svelte5-stack-converter/tests/toolchain`. On a fresh checkout, run `pnpm install --frozen-lockfile` in that directory to enable the production browser assertions. An alternate toolchain can be selected with `SVELTE_FIXTURE_NODE_MODULES`. Tests copy that input into temporary fixture projects. Set `SVELTE_FIXTURE_CHROME` when using an installed Chrome executable. The native WebGL fixture uses Playwright Chromium. A clean install here passed with esbuild 0.28.2. The pinned webcrack package declares Node 22/24 support; our fixture run used Node 26.13.1 and exercises a subset of its transforms.
